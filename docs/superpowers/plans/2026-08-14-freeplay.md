# Freeplay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `freeplay` tournament type whose leader is recorded per round, with no session-level leader at all.

**Architecture:** One incremental migration makes `tournaments.my_leader_id` nullable and adds a nullable `rounds.my_leader_id`. An exclusive-or invariant guarantees exactly one leader source per real round, so `coalesce(rounds.my_leader_id, tournaments.my_leader_id)` resolves for both modes without any query branching on type. Freeplay feeds matchup statistics and is filtered out of the headline record.

**Tech Stack:** Next.js 16 (App Router), React 19, Drizzle ORM + Postgres, TanStack Query, vitest, Tailwind.

**Spec:** `docs/superpowers/specs/2026-08-14-freeplay-design.md`

## Global Constraints

- **This is NOT the Next.js you know** (`AGENTS.md`). Read the relevant guide in `node_modules/next/dist/docs/` before writing framework-level code. No task here touches a framework API.
- **A freeplay session has NO leader.** `tournaments.my_leader_id` is null for it — not a default, not a starting deck, not a fallback. Every round carries its own.
- **The invariant, enforced as an exclusive-or:**
  - non-freeplay tournament → `my_leader_id` **required**; its rounds → **must be null**
  - freeplay tournament → `my_leader_id` **must be null**; its swiss/top_cut rounds → **required**
  - **byes and no-shows are exempt** — a freeplay bye may have a null leader.
- **Type changes into or out of freeplay are disallowed**, always — not merely once rounds exist.
- **Freeplay is INCLUDED in:** Matchups, By opponent, By meta, the leader selector, CSV export.
  **Freeplay is EXCLUDED from:** Overall (including `totalTournaments`, `bestMeta`, `mostPlayedLeader`) and Achievements.
- **`npm run db:generate` is safe** — `drizzle-kit generate` only diffs `schema.ts` against the migration journal and never connects to a database. **`npm run db:migrate` is NOT safe: `drizzle.config.ts` reads `DATABASE_URL`, which points at PROD Neon.** Never run `db:migrate` in these tasks.
- Tests run with `npm test` (vitest). `tests/setup/global-setup.ts` runs `migrate()` against `DATABASE_URL_TEST`, so **the migration file must exist before any test can pass** — that is why Task 1 comes first.
- **No component-test infrastructure exists** — `vitest.config.ts` is `environment: 'node'` and collects `.ts` only; `@testing-library/react` and `jsdom` are installed but unused; the `e2e` script has no Playwright config. Do NOT stand any of it up. UI tasks are verified by `npm run lint`, `npx tsc --noEmit`, a green suite, and the manual pass in Task 8.
- Commit after every task.

```ts
  // Client-generated so an offline create can be referenced by its rounds
  // immediately. Omitted by non-offline callers; the database defaults it.
  id: z.uuid().optional(),
  type: tournamentTypeEnum,
  // Required for every type except freeplay, which records the leader per

  myLeaderId: z.uuid().optional(),
  metaId: z.uuid().optional(),
  name: z.string().trim().max(120).optional(),

});
```

```ts
    .leftJoin(opponentMeta, eq(rounds.opponentMetaId, opponentMeta.id))
```

It must be a `leftJoin`, not an inner one: a freeplay session with no rounds yet has nothing to coalesce to, and an inner join would drop the session from the export entirely. `myLeader.name` is therefore `string | null` — the CSV writer already handles null cells for the other optional columns, so no change is needed there. Confirm `sql` is imported in this file.
